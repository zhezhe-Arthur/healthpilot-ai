# HealthPilot AI

**HealthPilot AI — 基于 AI Agent 的个人身心健康管理系统**

## 一、项目介绍

HealthPilot AI 是一个基于人工智能的个人健康管理项目，致力于帮助用户建立长期、可持续的健康生活方式。

项目不仅关注身体健康，也将心理健康纳入统一的健康管理体系，综合考虑以下五个维度：

- **运动管理**：日常活动、运动习惯、运动强度及恢复情况。
- **饮食管理**：饮食结构、营养习惯、饮水和饮食目标。
- **户外活动**：日照、自然环境接触、户外活动时间。
- **睡眠管理**：睡眠时长、睡眠质量和作息规律。
- **心理健康**：情绪状态、压力水平、心理负担及长期心理状态。

系统通过 AI Agent 分析用户的综合健康信息，生成个性化的健康提示和生活计划。

用户每天记录健康行为、身体状态和心理感受，系统定期分析执行情况与健康变化，并根据复盘结果更新健康画像，持续优化后续健康计划。

**项目的核心目标不是生成一次性的健康建议，而是构建一个能够持续了解用户、跟踪变化并调整建议的长期健康管理系统。**

## 二、核心业务流程

HealthPilot AI 采用持续循环的健康管理模式。

### 2.1 完整业务闭环

**健康画像 → 健康提示与综合计划 → 数据更新与反馈 → 数据复盘 → 健康画像更新 → 新一轮健康管理**

完整流程如下：

**第一阶段：建立健康画像**

用户首次使用系统时，填写个人基础健康信息、生活习惯、健康目标和当前身心状态。

系统将这些信息整合为统一的用户健康画像。

↓

**第二阶段：健康提示与计划生成**

AI Agent 根据当前健康画像，综合分析用户的身体状态、生活习惯、执行能力和个人目标。

生成每日、每周及每月的综合健康计划，并根据实际情况提供健康提醒和建议。

↓

**第三阶段：每日数据更新与反馈**

用户根据计划进行日常活动，并记录运动、饮食、户外活动、睡眠及情绪情况。

用户也可以通过自然语言向 AI 反馈身体感受、心理状态和计划执行困难。

↓

**第四阶段：周期性数据复盘**

系统结合用户的健康记录、计划执行情况和反馈内容，开展每日简要回顾、每周总结与每月综合复盘。

AI Agent 识别健康趋势、计划执行问题及需要调整的生活习惯。

↓

**第五阶段：更新健康画像**

系统根据复盘结果提出健康画像的更新建议。

经过必要的业务校验和用户确认后，更新相应的健康状态、行为习惯、目标及偏好。

随后基于更新后的健康画像生成下一周期的健康计划。

↓

**返回第一阶段，进入下一轮健康管理。**

这一流程不断重复，使健康管理从静态的信息记录转变为动态、持续的健康改善过程。

### 2.2 健康画像

健康画像是 HealthPilot AI 的核心数据基础，也是整个系统的长期上下文。

健康画像不仅包含用户首次填写的基础资料，还包含系统在长期健康管理过程中积累的相关信息。

主要内容包括：

| 数据类别 | 主要内容 |
|---|---|
| 基础信息 | 年龄、身高、体重等 |
| 身体状态 | 运动能力、活动水平、相关健康限制 |
| 饮食习惯 | 饮食结构、饮水情况、偏好与限制 |
| 户外习惯 | 户外活动频率、活动时间 |
| 睡眠状态 | 睡眠时长、规律、质量 |
| 心理状态 | 情绪、压力、心理感受及变化趋势 |
| 健康目标 | 体重管理、改善睡眠、增强体能、缓解压力等 |
| 用户偏好 | 时间安排、活动方式、饮食偏好 |
| 历史变化 | 周期性健康状态变化、目标调整和计划执行表现 |

健康画像不是一个永远不变的数据表。

系统会在长期使用过程中不断获取新信息，并通过复盘逐步完善健康画像。

例如：

- 用户长期无法完成高强度运动，系统可以建议降低运动强度。
- 用户连续多周睡眠不足，系统可以提高睡眠管理的优先级。
- 用户近期压力明显增加，系统可以建议调整计划安排，减少额外负担。
- 用户已稳定建立某种健康习惯，系统可以适当调整下一阶段目标。

需要区分用户的长期基础信息与短期状态变化，不应因为一次异常打卡就直接改写长期画像。

### 2.3 健康提示与综合计划

系统根据用户当前健康画像生成统一的健康计划，而不是分别生成五套相互独立的计划。

计划需要综合考虑身体健康、心理状态、用户目标和现实生活条件，避免不同健康目标之间产生冲突。

计划类型包括：

**每日计划**

提供可执行的日常任务，例如运动、饮食、户外活动、睡眠安排和情绪管理建议。

**每周计划**

安排运动频率、作息改善重点、饮食调整目标及心理健康关注事项。

**每月计划**

结合长期健康目标，确定阶段性改善方向，并通过月度复盘评估实施效果。

健康提示可以由多种事件触发：

- 根据时间和计划生成日常提醒。
- 根据用户近期记录提供适当建议。
- 根据用户主动提问提供健康信息。
- 根据周期复盘结果建议调整计划。

AI 生成的内容首先作为计划草案或建议，由 Java 业务服务进行校验，再按照业务规则保存或交由用户确认。

### 2.4 每日数据更新与反馈

用户每天通过打卡或自然语言交流记录自己的健康状态。

数据来源在规划上包括：

1. 用户手动填写的健康记录。
2. 每日健康任务的完成情况。
3. 用户与 AI Agent 的日常交流和反馈。
4. 未来经过授权接入的可穿戴设备或健康监测设备。

记录的重点不仅是用户是否完成任务，还包括任务执行后的实际感受。

例如：

- 今天是否完成运动？
- 运动后是否明显疲劳？
- 昨晚睡眠是否充足？
- 今天的情绪和压力如何？
- 当前计划是否影响工作或正常生活？

系统保留用户的原始记录，并将这些数据用于后续统计和复盘。

对于用户主动反馈的困难，系统可以及时提出临时调整建议，而不必等到周期结束。

### 2.5 数据复盘

数据复盘负责将分散的日常记录转化为有意义的健康变化信息。

系统计划提供三个层级的复盘：

| 复盘周期 | 主要内容 |
|---|---|
| 每日回顾 | 当天任务执行情况、异常反馈和简短建议 |
| 每周复盘 | 执行率、身心状态趋势、主要困难和下周调整建议 |
| 每月复盘 | 阶段性目标变化、长期习惯趋势和综合改善方向 |

复盘不仅关注任务完成率，还需要结合用户的实际状态进行综合判断。

例如，某用户本周运动完成率较低，但主要原因是连续加班和睡眠不足。

系统不应简单认定用户缺乏执行力，而应该结合睡眠、压力和工作情况，建议适当降低运动目标，并优先恢复正常作息。

复盘结果主要包括：

- 已完成的健康目标。
- 尚未达到的健康目标。
- 健康数据的变化趋势。
- 用户遇到的主要困难。
- 当前计划与用户实际情况的匹配程度。
- 下一周期建议调整的内容。

### 2.6 健康画像更新

这是整个系统形成闭环的关键环节。

系统根据数据复盘结果，识别需要更新的健康画像信息。

更新内容可能包括：

- 当前身体活动能力。
- 近期睡眠与生活规律。
- 情绪和压力状态。
- 用户已形成的长期习惯。
- 健康目标及优先级。
- 健康计划的执行偏好和限制条件。

对于需要长期保留或可能影响后续计划的重要信息，系统应保留修改记录，并根据实际情况要求用户确认。

**复盘不是直接替代健康画像，而是为健康画像提供经过分析和校验的更新依据。**

更新后的健康画像将用于下一轮 AI 计划生成，使系统逐步适应用户真实的生活方式。

## 三、典型使用场景

假设一名用户希望改善身体状态、睡眠质量并减轻工作压力。

**第一周：初始健康画像**

系统了解到：

- 用户平时久坐，运动较少。
- 工作日睡眠时间偏短。
- 经常感觉工作压力较大。
- 希望逐步增加运动量并改善睡眠。

AI 根据这些信息生成第一周的综合计划，包括适量步行、调整就寝时间、安排户外活动以及进行简短的压力调节练习。

**第一周：执行与数据更新**

用户在日常打卡中反馈：

- 大部分步行任务可以完成。
- 部分晚上因工作加班而延迟睡觉。
- 高压力工作日不愿意额外安排运动。
- 周末户外活动后主观感受有所改善。

**第一周：数据复盘**

系统综合分析后认为：

- 当前步行计划基本可行。
- 睡眠安排仍与工作时间存在冲突。
- 运动任务需要考虑高压力工作日的实际执行能力。
- 户外活动可以继续作为健康计划的一部分。

**第二周：健康画像更新**

系统提出更新建议：

- 将工作日时间限制加入计划偏好。
- 调整睡眠改善的阶段性目标。
- 将高压力日期的活动安排设置得更加灵活。

经用户确认后，系统更新健康画像，并生成更符合实际情况的第二周计划。

此后持续重复这一过程。

这体现了项目的核心价值：

**AI 不只是告诉用户应该如何生活，还需要结合真实反馈，逐步学习什么样的健康生活方式适合当前用户。**

## 四、系统技术架构

HealthPilot AI 采用前后端分离架构，并将传统业务服务与 AI Agent 服务分开。

### 4.1 技术栈

| 模块 | 技术选型 | 主要职责 |
|---|---|---|
| Web 前端 | React + TypeScript | 健康画像展示、打卡、计划、复盘与 AI 对话 |
| Java 后端 | Java 17 + Spring Boot 4.1.2 | 用户管理、业务规则、权限、数据读写 |
| AI Agent | Python + LangChain / LangGraph | 综合健康信息分析、计划建议、复盘和对话 |
| 数据库 | MySQL 8 | 用户、健康画像、计划、打卡、复盘及历史记录 |
| ORM | Spring Data JPA + Hibernate | Java 实体映射与数据库访问 |
| 数据库迁移 | Flyway | 数据库表结构及版本管理 |

### 4.2 服务协作方式

**React 前端 → Java Spring Boot → MySQL**

负责用户管理、业务数据查询、保存、权限验证和日常功能。

**React 前端 → Java Spring Boot → Python Agent**

负责需要 AI 参与的健康计划生成、智能分析、复盘和对话。

**Python Agent → 受控 Java 业务接口 → MySQL**

AI Agent 通过经过权限验证的业务接口获取必要数据，而不是直接拥有任意数据库修改权限。

AI 可以根据健康画像和历史记录提出建议，但业务规则、数据持久化及重要数据变更仍由 Java 后端控制。

### 4.3 AI Agent 的主要职责

计划中的 Agent 能力包括：

- 综合读取用户授权的健康画像与近期记录。
- 生成统一的每日、每周和每月健康计划。
- 根据用户日常反馈提供健康提示。
- 分析健康数据及计划执行情况。
- 生成周期性复盘报告。
- 提出健康画像更新建议。
- 通过长期上下文保持建议的连续性。

Agent 可以使用工具调用、短期对话状态、长期数据存储和必要的人工确认机制，构成可控制、可追踪的 AI 工作流。

## 五、核心数据设计

系统围绕健康管理闭环组织业务数据。

| 数据实体 | 作用 |
|---|---|
| `users` | 保存用户账号信息 |
| `health_profiles` | 保存用户统一健康画像 |
| `health_goals` | 保存长期与阶段性健康目标 |
| `health_plans` | 保存综合健康计划 |
| `plan_tasks` | 保存计划中的具体任务 |
| `daily_checkins` | 保存用户每日健康数据 |
| `task_logs` | 保存健康任务执行情况 |
| `health_reviews` | 保存周期性健康复盘 |
| `plan_revisions` | 保存健康计划调整记录 |
| 健康画像变更记录 | 追踪健康画像的重要更新及依据 |

上述数据实体构成后续规划，实际表结构将通过 Flyway 按模块逐步实现。

完整的数据闭环是：

**读取健康画像 → 生成健康计划 → 保存任务 → 收集每日反馈 → 分析与复盘 → 更新画像 → 生成下一轮计划**

所有重要数据都应支持用户身份隔离、访问控制和必要的历史追溯。

## 六、项目设计原则

### 6.1 身心健康统一管理

运动、饮食、户外、睡眠和心理状态相互影响，不应该被设计成完全割裂的独立系统。

AI 必须从用户整体生活状态出发生成综合建议。

### 6.2 长期持续优化

健康管理不是一次性问答，而是持续循环的过程。

系统通过长期积累的健康记录和复盘结果，不断优化用户画像与未来计划。

### 6.3 以实际执行能力为中心

健康计划不仅需要合理，还需要能够融入用户的日常生活。

当用户无法完成计划时，应分析实际原因，而不是机械地增加任务或施加压力。

### 6.4 AI 建议与业务控制分离

AI 主要负责分析和建议。

Java 后端负责身份认证、权限校验、业务规则和数据写入。

重要修改应经过相应的校验与确认，避免 AI 无依据地修改用户资料。

### 6.5 用户隐私与数据安全

健康信息具有较高敏感性，系统设计应考虑：

- 最小必要的数据收集。
- 用户数据访问权限隔离。
- 账号凭证和敏感配置安全管理。
- 对 AI 工具调用进行权限控制。
- 健康数据重要变更记录。
- 不在公开代码仓库提交真实用户健康信息。

### 6.6 健康辅助而非医疗诊断

HealthPilot AI 定位为个人健康与生活方式辅助工具。

AI 提供的提示和计划不应被描述为医疗诊断、处方或专业心理治疗的替代品。

对于可能存在严重健康风险或心理危机的情况，系统应优先引导用户获取适当的专业帮助。

实现并验证：

**健康画像 → 健康提示与计划 → 数据更新 → 数据复盘 → 健康画像更新**

使系统具备基本的长期个性化健康管理能力。

## 九、项目愿景

HealthPilot AI 希望实现一种持续、个性化的健康管理方式。

传统健康记录工具主要解决“记录了什么”的问题。

普通 AI 问答工具主要解决“现在应该怎么做”的问题。

HealthPilot AI 进一步关注：

- 用户目前处于什么状态？
- 用户真正能够执行什么计划？
- 用户执行后的效果如何？
- 用户的身体与心理状态发生了什么变化？
- 下一阶段应该如何调整？

通过统一健康画像、日常健康管理、持续反馈与周期复盘，逐步形成一个长期、动态、可解释的个人健康管理闭环。

**让 AI 不仅能够提出健康建议，还能持续结合用户的实际生活情况优化建议。**
