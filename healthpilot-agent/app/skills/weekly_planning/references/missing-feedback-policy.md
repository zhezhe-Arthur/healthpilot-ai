# 缺失反馈：跨 Skill 共同决策表

项目规则，非医学指南。weekly_planning 与 exercise 必须共同遵守。缺少反馈本身不等于健康异常，也不是安全许可。

| 输入情形 | 可用信息与处理 | 无法交互时的输出语义 |
|---|---|---|
| 最近已确认计划存在；只有本周完成/恢复反馈缺失；原活动有明确适用依据；已知限制仍明确且不冲突；没有未解决安全问题、过期条件或需要重新专业许可的事项 | 可沿用偏好、时间与原有低负担活动，保留来源日期；不增加频率、时长、强度、负重，不引入新动作或用未知依据替换；不声明当前恢复良好 | conditional_draft：条件性保守草稿；完成/恢复未知，执行前需确认当前适用性，仍待用户确认 |
| 已知疼痛、异常、住院/手术后限制未解决；活动依赖的专业许可缺失或失效；关键禁忌/限制、活动剂量依据不明；资料冲突或缺文件 | 先提出必要问题；不通过降低强度假装解决安全缺失 | awaiting_clarification：受影响领域不列可执行任务，输出原因、缺失项和问题；其余有依据领域继续 |
| 没有可用已确认计划或缺乏首次规划基础 | 不能编造延续计划；可讨论偏好或补充资料 | awaiting_information：受影响部分仅列待补充信息 |
| 当前明显急性严重异常 | 按各 safety.md 优先求助，停止普通计划建议 | safety_escalation：不能等待下周或后台通知 |

这些是输出语义标签，尚非 Java 枚举或已实现接口字段；不得直接假定后端接受。计划整体仍是待确认草稿。领域暂停不等于全计划失败，也不允许综合规划重新补回被运动 Skill 暂停的任务。

“没有未解决问题”必须来自可用记录核对，不是从未回复推断。仅知上周计划存在，无法确认其安全依据/限制时，走 awaiting_clarification，而非默认沿用。普通偏好可以保留；临床许可不可因历史存在而自动视为仍有效。

正式日期按 integration-rules.md 的 Java 自然周契约处理。
